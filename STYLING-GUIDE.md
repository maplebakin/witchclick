## 🗺️ Style Location Decision Tree

**When you need to style something, where should it go?**

```
┌─ Is it a design token (color, spacing, font)?
├─ YES → tokens.css
└─ NO ↓

┌─ Is it a card-related style?
├─ YES → cards.css
└─ NO ↓

┌─ Is it admin panel only (WCAG AA)?
├─ YES → admin.css
└─ NO ↓

┌─ Is it navbar/header specific?
├─ YES → Header.astro <style is:global>
└─ NO ↓

┌─ Is it component-specific and won't be reused?
├─ YES → Component's <style> block (scoped)
└─ NO ↓

┌─ Is it page-specific layout/styling?
├─ YES → Page's <style> block
└─ NO ↓

Default → base.css (with appropriate section comment)
```

## 🎯 Key Styling Patterns

### **1. CSS Custom Properties Cascade**

```
tokens.css (base tokens)
  ↓
color-tokens.generated.css (overrides)
  ↓
themes.generated.css (theme-specific)
  ↓
base.css (uses tokens)
  ↓
Component styles (inherit + override)
```

**Example:**
```css
/* tokens.css */
--text-body: rgba(249, 245, 255, 0.82);

/* base.css */
p {
  color: var(--text-body);
}

/* Component.astro <style> */
.special-text {
  color: var(--text-body);
  font-size: 1.1rem; /* Component-specific */
}
```

---

### **2. Scoped vs Global Styles**

#### **Scoped** (`<style>`)
- **Default for all components**
- Auto-prefixed with unique hash
- Cannot affect child components
- Keeps styles encapsulated

```astro
<!-- Component.astro -->
<style>
  .card { /* Only affects this component */
    padding: 1rem;
  }
</style>
```

#### **Global** (`<style is:global>`)
- **Only used in Header.astro**
- No scoping, affects entire page
- Use sparingly, only when necessary
- For navbar overrides and extensions

```astro
<!-- Header.astro -->
<style is:global>
  .site-nav__actions { /* Affects all pages */
    gap: var(--space-3);
  }
</style>
```

### **3. Responsive Strategy**

**Mobile-First Approach:**
- Base styles target mobile devices
- Progressive enhancement for larger screens

**Primary Breakpoint:** **920px**

```css
/* Mobile: Default (< 920px) */
.site-nav__list {
  display: none; /* Hidden on mobile */
}

.site-nav__toggle {
  display: inline-flex; /* Menu button visible */
}

/* Desktop: (≥ 921px) */
@media (min-width: 921px) {
  .site-nav__list {
    display: flex; /* Show full nav */
  }

  .site-nav__toggle {
    display: none; /* Hide menu button */
  }

  .site-nav__actions {
    display: flex; /* Show action buttons */
  }
}
```

**Other Breakpoints:**
- Defined in `base.css` design tokens (line ~60)
- Used throughout components for responsive behavior

## 📐 Layout Structure

### **CSS Import Order** (in `Base.astro`)

```javascript
import "@/styles/base.css";      // 1️⃣ Foundation
import "@/styles/cards.css";     // 2️⃣ Components
import "@/styles/tailwind.css";  // 3️⃣ Utilities
```

**Why this order?**
1. Base provides foundations and tokens
2. Cards builds on base styles
3. Tailwind provides utility overrides

### **Selector Specificity Strategy**

```
Low specificity  →  High specificity
────────────────────────────────────
tokens.css       →  base.css  →  cards.css  →  component styles
(variables)         (defaults)   (patterns)    (specifics)
```

## 🎨 Color System Architecture

### **Color Token Flow**

```
1. tokens.css
   ↓ Defines base tokens
   --surface-card: rgba(20, 10, 33, 0.78);

2. color-tokens.generated.css
   ↓ Can override base tokens
   --surface-card: rgba(25, 15, 38, 0.80); /* Custom override */

3. themes.generated.css
   ↓ Theme-specific variations
   :root[data-theme="cozy-dawn"] {
     --surface-card: rgba(240, 235, 245, 0.95);
   }

4. base.css
   ↓ Uses tokens in rules
   .card {
     background: var(--surface-card);
   }
```

### **Theme System**

**Current Themes:**
- 🍂 Autumn Twilight (midnight mode)
- 🌅 Cozy Dawn (dawn mode)
- 🌙 Cozy Midnight (midnight mode)
- 🌾 Golden Harvest (dawn mode)

**Theme Toggle:**
- User preference stored in localStorage
- Applied via `data-theme` attribute on `:root`
- CSS custom properties update automatically

## 🛠️ Development Workflow

### **When to Regenerate CSS**

```bash
npm run prebuild  # Generates themes + checks
```

**Regenerates:**
- `themes.generated.css`
- `themes.generated.json`
- `color-tokens.generated.css` (if configured)

### **Build Process**

```bash
npm run build
```

1. Runs `prebuild` scripts
2. Generates theme CSS
3. Compiles Astro + processes CSS
4. Bundles and optimizes
5. Outputs to `dist/`

### **Development Server**

```bash
npm run dev
```

- Hot module replacement for CSS changes
- Instant preview of style updates
- CSS sourcemaps for debugging
