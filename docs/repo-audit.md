# WitchClick Audit

## Overview
WitchClick is a static Astro site for long-form ritual content, supported by a custom ingestion pipeline (`scripts/ingest.mjs`) and runtime utilities for posts, entities, and monetization. The current codebase offers a solid content experience, but targeted investments will increase maintainability, production readiness, and organic reach.

## Functionality Recommendations
1. **Align ingestion output with runtime loaders.** The ingestion script can emit Markdown files under either `content/posts` or `src/content/posts`, but the runtime loader only reads from `content/posts`, so content saved to the modern collection path will be invisible at build time.【F:scripts/ingest.mjs†L96-L121】【F:src/utils/posts.ts†L33-L55】 Update `loadAllPosts()` to resolve whichever directory exists (prefer the collection path) so new adopters are not surprised by missing posts.
2. **Introduce schema validation for ingestion specs.** `scripts/ingest.mjs` trusts inbound JSON, only normalizing primitives before writing frontmatter.【F:scripts/ingest.mjs†L31-L94】 Add JSON schema or Zod validation (and surface actionable errors) to prevent malformed affiliate anchors, invalid dates, or missing slugs from reaching content.
3. **Harden HTML sanitization for Markdown rendering.** Post pages currently strip `<script>` tags and inline handlers via regex after parsing Markdown.【F:src/pages/post/[slug].astro†L68-L125】 Replace this with server-side DOMPurify (already declared in dependencies) to reduce XSS risk from embedded HTML without brittle regex maintenance.
4. **Broaden automated test coverage.** Only a single unit test exists, focused on affiliate linkification, leaving ingestion, pagination, and rendering helpers unverified.【F:tests/pipeline.test.ts†L1-L15】 Add Vitest coverage for `loadAllPosts`, pagination, reading-time estimation, and entity resolution to guard against regression as the content model evolves.
5. **Document and assert settings contract.** The base layout accesses several theme and brand settings without runtime checks.【F:src/layouts/Base.astro†L5-L102】 Define a typed settings module (with defaults and validation) so configuration changes fail fast and remain discoverable.

## Utilization & Operations Recommendations
1. **Codify the publishing workflow.** The repo includes a `ship.sh` helper and ingestion CLI, but the README lacks guidance on how they interact.【F:scripts/ship.sh†L1-L23】【F:README.md†L1-L4】 Expand documentation (or add `/docs/publishing.md`) covering prompt generation, ingestion, review, and deployment so contributors can reproduce the pipeline.
2. **Add continuous integration.** With scripts for `npm run check`, `npm run build`, and `npm run test`, introduce a GitHub Actions workflow to execute them on every push. This ensures ingestion or content changes do not silently break builds before `scripts/ship.sh` runs locally.【F:package.json†L6-L32】
3. **Expose operational metrics for ingestion failures.** `scripts/ingest.mjs` fails fast with console messages but provides no logs or summary outputs for batch operations.【F:scripts/ingest.mjs†L31-L144】 Add structured logging (e.g., JSON lines) and exit codes consumable by automation, enabling nightly bulk ingests or scheduled validations.
4. **Cache-bust post loader during dev servers.** `loadAllPosts()` memoizes content for performance, but the cache is never invalidated, so newly added Markdown files require a server restart in development.【F:src/utils/posts.ts†L13-L48】 Gate caching behind `import.meta.env.PROD` or add a manual invalidation hook to keep authoring sessions responsive.

## Visibility & Growth Recommendations
1. **Expand structured data coverage.** Individual posts output `BlogPosting` JSON-LD, but collection pages (home, tag, downloads) omit `ItemList` or `CollectionPage` schemas.【F:src/pages/index.astro†L1-L113】【F:src/pages/post/[slug].astro†L126-L199】 Adding structured data improves SERP rich result eligibility for curated lists and printable assets.
2. **Centralize canonical URL derivation.** Several pages build canonicals from `readSettings()` and fall back to a placeholder origin.【F:src/layouts/Base.astro†L17-L66】【F:src/pages/post/[slug].astro†L45-L70】 Move origin enforcement into settings (with validation and environment fallbacks) to avoid shipping `https://example.com` canonicals when misconfigured.
3. **Surface evergreen CTAs and social proof.** The home page emphasizes latest posts, but lacks sections for newsletter signup, testimonials, or category discovery that encourage repeat visits.【F:src/pages/index.astro†L23-L113】 Introduce modular blocks (newsletter, seasonal collections) managed via settings or content files to improve conversion and time-on-site.
4. **Instrument audience analytics & attribution.** No analytics or event tracking is currently injected in the base layout.【F:src/layouts/Base.astro†L5-L199】 Add privacy-conscious analytics (Plausible, Fathom) and outbound link tracking to understand content performance and optimize affiliate placement.

## Next Steps
Prioritize functional fixes (ingestion alignment, validation, sanitization) to protect content integrity, then invest in CI and documentation so contributors can operate the pipeline confidently. After the foundation is stable, expand structured data and conversion-oriented modules to improve visibility and monetization.
